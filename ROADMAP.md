# Arena Stream — Transition Roadmap

## Phase 0 — Reality check
Document the existing prototype without pretending it is the target game.

## Phase 1 — Core combat prototype
Build only: one arena, one player, one weapon, movement, attack, hit detection, one simple AI enemy, death/restart.
Success: combat itself is worth continuing.

## Phase 2 — AI pressure
Add enemy spawning, basic behaviors, waves, escalation and one elite enemy.
Success: four players could plausibly have a tense cooperative fight.

## Phase 3 — Four-player co-op
Introduce 4-player cooperative room, authoritative server, synchronized AI, leave/reconnect handling and a simple queue placeholder if needed.
Success: four players can complete a short match reliably.

## Phase 4 — Show layer
Add timer, stages, dramatic events, final objective and spectator-readable HUD.
Success: a non-player can understand the match while watching.

## Phase 5 — Audience layer
Add checkpoint voting, 2–3 controlled choices and anti-griefing.
Success: audience interaction makes the match more interesting without making it unfair.

## Phase 6 — Content pipeline
Explore event logging, highlight markers, replay/event data, clip candidates and Shorts workflow.

## Phase 7 — Distribution
Only after the game works: YouTube Live workflow, channel format, Shorts distribution, and Playables research/integration if officially available and economically sensible.

## Phase 8 — Scale
Only after real usage: matchmaking, persistent progression, more maps, stronger backend and monetization.

## Kill criteria
Redesign or stop the direction if combat is not enjoyable, AI combat is unreadable, co-op adds little, spectators cannot understand the action, audience interaction is annoying, matches lack memorable moments, infrastructure costs become disproportionate, or the concept requires an impractically large team.
