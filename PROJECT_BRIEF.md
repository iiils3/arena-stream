# Arena Stream — Project Brief

## Mission
Build a low-cost, browser-first Medieval combat game that doubles as a live entertainment format and a repeatable YouTube content engine.

## Product triangle
GAME — compact cooperative combat.
SHOW — escalation, tension, audience interaction and a clear ending.
CONTENT ENGINE — matches can become live streams, highlights, Shorts and videos.

## Target product
- 4 human players
- AI-controlled enemy army
- escalating stages
- approximately 10-minute match
- controlled audience voting/events
- final objective / throne concept
- Medieval melee inspired by the feel of games such as Chivalry, without copying them

## Business constraint
Initial goal: zero / near-zero upfront cost.

## Core hypothesis
If a short cooperative match is fun to play AND fun to watch, the same product can generate players, streams, clips, Shorts, community activity and data for iteration.

## Must prove
- Combat is fun.
- AI creates meaningful pressure.
- Four-player cooperation works.
- Matches are short enough to replay/watch.
- Audience interaction improves the show.
- The game produces clip-worthy moments.
- Development remains low-cost.

## Must NOT be assumed
- YouTube Playables availability.
- Monetization availability in every market.
- Revenue.
- Viral growth.
- Large player numbers.
- Full automation.
- Final visual/game design.

## Current repository reality
The existing repository is a legacy PvP prototype/scaffold. It contains useful multiplayer, HUD, weapons, voting and browser infrastructure, but it does not yet represent the target 4-player-vs-AI concept.

Reuse what is valuable. Rewrite what conflicts. Do not let the old prototype dictate the new product.

## Decision rule
Every major feature must answer:
1. Does it improve player experience?
2. Does it improve spectator experience?
3. Does it create useful content?
4. Is it affordable?
5. Is it technically justified?
6. Can we test it cheaply?

If not, postpone or remove it.
